# About This Manual

Writing documentation is hard.

Not only in writing it well, but also in keeping it up-to-date. It's also hard to keep track of all the changes made in software, and when you're creating the software, creating the documentation is a huge undertaking in it's own right.

In my opinion, Bidule suffers from not having a good pedegogical resource. This is of particular importance for new users, many of whom are not experienced with Bidule, let alone DSP, MIDI or visual programming in general. In short, it can be a make or break moment for someone to get started with Bidule, because when you hit a wall immediately, with no helpful doors to open, it's a show-stopper. This might lead to someone giving up on Biduler and try one of the other visual programming platforms (Pure Data, Max, etc.) that arguably offer much better documentation, but equally a much steeper learning curve and up front complexity. Some people love the complexity, but Bidule I find is the right balance of complexity and actually making meaningful sound and music.

This manual was created to help plug the gap, in the jope that other experienced users of Bidule will contribute to make it a better resource. Think of it as a love-letter for all those years of invaluable usefulness and sound and music creation it's provided to its long-time users. It doesn't get enough due credit.

In fact there is an official manual. You can find it [here](https://plogue.com/bidule-manual). But it has fallen behind that many updates that have be contributed to Bidule, and in need of an update. This aims to be be stop gap, using a platform that is easier to maintain and update, and accessible for contributors.

Also, think of it an an open source project. I hope other users find it useful, but jump in and contribute, which goes back to the first line or this section. Crowdsourcing is a great way to get things done. This by myself would take a lot of time.

## About Plogue Bidule

It is a standalone application, and also a VST/VST3/AU plugin. It runs on both Mac and Windows.

It ships many useful objects (actually called bidules) that help you fix shortcomings or enable you to achieve soemthing that your DAW makes very challenging to achieve. You can combine these objects into groups, and group these groups into more complicated setups. You can map parameters to anything. Modular, remember?

A lot of film & video game composers use Bidule to manage their huge multi-plugin setups that is cumbersome in DAWs...

1. So, Bidule is also a very flexible plugin-host. Bidule is problem solver.

2. Bidules is a low-level DSP toolbox. Osciallators, filters, maths & logic, spectral processing, routing, MIDI, etc. It's a toolbox for making cool stuff. With this you can make delay-based effects (reverbs, echos, chorus, granular etc), intruments (wavetable, subtractive, additive, sample-based etc), sequencers (step, algorithmic, euclidean etc) and more.

3. Bidule has an SDK for developing custom plugins, if you want to go lower still. I even use it as an environment to test my own plugins.

It would be fair to say that a lot of folk only use Bidule for the first point.

This manual is mainly focused on the last two points. These need more clarity: on the inputs and outputs, what parameters and values the objects require to even do anything.
